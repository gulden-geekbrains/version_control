# Инструкция к GIT

**Git** — это специальная программа, которая позволяет отслеживать любые изменения в файлах, хранить их версии и оперативно возвращаться в любое сохранённое состояние. 

## Команды в GIT



## Ветки

```sh
git branch 
```

Показывает список всех имеющихся веток. По умолчанию, будет только master, первоначальная.

```sh
git branch (имя ветки)
```

Вместо (имя ветки) вписываем любое название - создаётся новая ветка. Писать стоит без пробелов

```sh
git checkout (имя ветки)
```

Переход на любую созданную ветку. Если вставить master вместо (имя ветки), то перейдём в главную ветку.

```sh
git branch -d (имя ветки)
```

Удаляет ветку.

```sh
git merge (имя ветки)
```

Соединяет указанную ветку с той, в которой находимся.

*Может возникнуть конфликт, Гит предложит выбор, какую версию хотим сохранить*

# GITHUB

GITHUB - крупнейший веб-сервис для хостинга IT-проектов и их совместной разработки.

Кроме размещения кода, участники могут общаться, комментировать правки друг друга, а также следить за новостями знакомых.

С помощью широких возможностей Git программисты могут объединять свои репозитории — GitHub предлагает удобный интерфейс для этого и может отображать вклад каждого участника в виде дерева.

Алгоритм действий:

1. Создать аккаунт на github.com
2. Создать локальный репозиторий.
3. Подружить локалку с удалёнкой. GITHUB при создании нового репозитория подскажет как это сделать.
4. Отправить push через локальный GIT, возможно, придётся пройти авторизацию.
5. Внести изменения онлайн или с другого компьютера
6. Pull изменения в локальный репозиторий, решить конфликты, если будут.

Можно принять участие в чужих проектах, даже если они закрыты от изменений для сторонних участий. Дляя того, чтобы предложить свою версию:

1. Используем команду Fork, чтобы клонировать необходимый репозиторий. Таким образом он оказывается у вас в библиотеке.
2. В локалке: git clone "ссылка на форкированный репозиторий". Должна появиться папка в локальном репозитории.
3. Вносятся изменения.
4. Push-им изменения в форкированный репозиторий в онлайне.
5. Pull-request (если кнопки нет, заходим в меню Contribute) изменённый файл. Владельцу оригинального репозитория придёт предложение внести ваши изменения.
